# 개미수열 (Look and Say Sequence)

양의 정수 `n`(3 < n < 100)이 주어질 때, n번째 항 `Lₙ`의 가운데 두 자리를 반환합니다.

```
n=5 → L5 = 111221     → "12"
n=8 → L8 = 1113213211 → "21"
```

## 실행

```bash
pnpm install
pnpm --filter algorithm test
```

TypeScript · Vitest · pnpm workspace

## 풀이

`'1'`에서부터 n회 반복하여 다음 항을 누적 도출합니다.
이전 항을 읽는 로직은 재사용이 가능하기 때문에, 재귀 함수를 활용하였습니다.

`reduce`로 한 번만 순회하면서 연속 구간을 누적하고, 현재 문자가 다음 문자와 다를 때만 새 묶음을 엽니다. 이중 순회 없이 한 번의 스캔으로 그룹핑이 끝납니다.

`term`을 두 번째 매개변수로 분리해, 임의의 문자열에서 원하는 단계만큼 진행할 수 있게 했습니다.

n ≥ 2 부터 각 항은 `(개수)(숫자)` 쌍의 나열이라 **길이가 항상 짝수**이므로, 가운데 두 자리는 `slice(mid-1, mid+1)`로 바로 얻습니다.

## 복잡도

항의 길이는 단계마다 **약 1.3036배**씩 증가합니다 (실측값 — Conway 상수 λ≈1.303577과 일치).

- **시간** O(λⁿ) — 각 단계에서 항 전체를 1회 순회
- **공간** O(λⁿ) — 최종 항 문자열 저장
- **재귀 깊이** O(n) — n < 100 이므로 스택 한계와 무관

### 실측

| n | 길이 | 시간 |
|---|---|---|
| 40 | 63,138 | 6ms |
| 50 | 894,810 | 103ms |
| 55 | 3,369,156 | 507ms |
| 60 | 12,680,852 | 2,234ms |
| 62 | — | 힙 부족으로 종료 (4GB 기준) |

**n=62에서 메모리 한계에 도달합니다.** n=99의 항 길이는 위 증가율로 약 3.9×10¹¹ 자로 추정되어, 문자열을 전부 생성하는 방식으로는 도달할 수 없습니다.

## 한계와 개선 방향

전체 문자열을 만들지 않고 **길이만 계산해 가운데가 속한 구간으로 내려가는** 방식이 필요합니다.

항을 특정 위치에서 자르면 이후 단계에서도 양쪽이 서로 영향을 주지 않는 지점이 존재하며, 이 경우 조각별 길이만 구해 목표 위치가 속한 조각만 추적할 수 있습니다. 조각이 반복 등장하므로 `(조각, 남은 단계) → 길이` 메모이제이션이 가능합니다.

다만 절단 가능 여부 판정이 간단하지 않았습니다. 경계의 숫자만 비교하는 것으로는 불충분하고, 실험 결과 **경계상 문제없어 보이는 절단점이 7단계 뒤에 깨지는** 경우가 확인되었습니다. 몇 단계까지 검증해야 충분한지 근거를 세우지 못해 이번 제출본에서는 제외했습니다.
